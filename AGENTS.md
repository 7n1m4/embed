# Repository Guidelines

## Project Overview
AnimaEmbed: OpenAI-compatible embedding service for `microsoft/unixcoder-base` on GTX 1050 (2GB VRAM) via ONNX Runtime CUDA. Designed for dual-GPU setups — targets the GTX 1050 exclusively while other GPUs remain idle.

## Architecture & Data Flow
FastAPI app (`embedding_service.py`) → POST `/v1/embeddings` endpoint → ORT inference on CUDA → mean pooling (NumPy) → OpenAI-shaped JSON response. Single-file architecture with no abstraction layers. ORT returns NumPy arrays, not torch tensors.

Key data path:
1. Request received with `input` (str or list[str]) and `model`
2. Tokenizer (lazy-loaded on first request, stored on `app.tokenizer`) produces NumPy tensors
3. `app.model` (ORTModelForFeatureExtraction, loaded once at startup) runs inference → `last_hidden_state`
4. `mean_pooling()` reduces (batch, seq, hidden) → (batch, hidden) embeddings
5. Response shaped as OpenAI Embeddings API JSON

## Key Directories
Flat structure — all modules at repository root. No `src/`, `tests/`, or subdirectories.

```
animaembed/
├── embedding_service.py    # All app logic, models, pooling, endpoint, entry point
├── export_model.py         # One-time model conversion (PyTorch → ONNX, CPU-only)
├── run-embed-service.sh    # Production launch wrapper
├── requirements.txt        # Python dependencies
├── README.md               # Setup and deployment documentation
├── AGENTS.md               # This file
└── .gitignore
unixcoder-onnx/             # Gitignored — generated by export_model.py
```

## Development Commands
| Action | Command |
|--------|---------|
| Install deps | `pip install -r requirements.txt` |
| Export ONNX model (one-time, CPU) | `python export_model.py` |
| Run service | `python embedding_service.py --gpu-index N` |
| Production wrapper | `bash run-embed-service.sh` (edit `GPU_INDEX` first) |
| Test endpoint | `curl -X POST http://localhost:8000/v1/embeddings -H "Content-Type: application/json" -d '{"input": "text", "model": "unixcoder-base"}'` |

Run the service with `workers=1` (default). Each worker loads a full model copy into VRAM — the 2GB GTX 1050 cannot hold more than one.

## Code Conventions & Common Patterns
- **No `async def` for handlers**: Use plain `def` — ORT inference blocks CPU/GPU; `async def` would serialize concurrent requests (FastAPI runs `def` handlers in a threadpool automatically).
- **Pydantic v2 `BaseModel`** for all request/response schemas: `EmbeddingRequest`, `EmbeddingData`, `EmbeddingResponse`.
- **NumPy everywhere**: ORT returns `np.ndarray`; pooling operates on NumPy arrays — no torch tensors after model export.
- **State on `app`**: Model and tokenizer are lazily initialized and stored as `app.model` / `app.tokenizer`. No DI container.
- **Type hints** used throughout.
- **GPU isolation via env**: `CUDA_VISIBLE_DEVICES` is set in the `if __name__ == "__main__":` block *before* any CUDA import, preventing ORT from seeing other GPUs.

## Important Files
- **`embedding_service.py`** — Main FastAPI app, `/v1/embeddings` endpoint, ORT model loading, mean pooling, CLI arg parsing. This is the only file that needs modification during normal development.
- **`export_model.py`** — Exports `microsoft/unixcoder-base` to ONNX via `optimum.exporters.onnx.main_export` (CPU-only). Run once to create `unixcoder-onnx/`.
- **`run-embed-service.sh`** — Production launch wrapper; hardcodes `GPU_INDEX=1` — edit per-machine before use.
- **`requirements.txt`** — `fastapi`, `uvicorn[standard]`, `transformers>=4.30.0`, `optimum[onnxruntime]>=1.12.0`, `torch`.

## Runtime/Tooling Preferences
- **Runtime**: Python 3.8+, CUDA Toolkit, `onnxruntime-gpu` matching CUDA version
- **Package manager**: pip only — no pyproject.toml, setup.py, or conda
- **No build step** — Python scripts run directly
- **No containerization** — Docker not configured
- **Production deployment**: systemd unit template referenced in README but not present in repo (private runbook)

## Testing & QA
- **No test suite exists** — no pytest, no unit tests, no CI config
- **No lint/format tools** configured (ruff, black, mypy, etc.)
- **Manual verification only**: curl the running service against `/v1/embeddings`
